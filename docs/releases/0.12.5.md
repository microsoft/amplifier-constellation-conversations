# Conversations 0.12.5

Companion can receive the saved status of a pending request while conversation
continues. Only the exact call-local pending receipt uses this quiet path. Spoken
answers and other observations still wait for the conversational floor, and the
original source, private audience, and terminal state are checked before delivery.
Repeated polling does not create more announcements or backend work.

The Minecraft observer now preserves recorded work-resumption facts from the
original request. Scheduled work, a recorded execution start, current activity,
and task completion remain distinct. Missing evidence stays unknown, omissions
are explicit, and empty optional evidence does not repeat an unchanged reply.
Reading these facts does not resume or renew work.

This release includes the executable and an updated `minecraft-observe.py`.
Installations using remote observer helpers must update their actual configured
helper locations as well as the executable, preserving adjacent instruction
helpers and installation configuration. Dependencies, model settings, voice
guidance, and provider protocols are unchanged.

Source and integration checks cover quiet delivery during continuing input,
deferred spoken results, source identity, interrupted delivery, and bounded
historical facts. The earlier recorded-voice trial remains 12 of 13 checks passed:
an early compound refinement caused an unnecessary backend prompt. This release
does not claim universal elimination of redundant delegation, proven silence
after provider acceptance, or long-duration voice quality.
