# Conversations 0.13.0

This release collects the changes since 0.12.8: Conversations delivery and view
fixes, native application packages, and the already merged Companion background
reply improvements. Within each installation, Conversations and the optional
Companion experience share one executable and application database.

## Conversations

- Delayed view updates preserve newer user intent. Reset and access changes clear
  private view state, and late reads cannot restore stale selections or content.
- An authenticated caller can inspect an original submission after it leaves the
  recent delivery list. The lookup uses the original saved message and delivery
  records; it does not resend the message or create a replacement request.
- Compatible Instance endpoints can expose original-session delivery receipts
  and work references through negotiated source-delivery support. Inspection
  retains the original source identity and current access checks. Unsupported or
  uncertain outcomes remain explicit; a saved submission is not proof of work
  completion or recipient attention.
- Completed turns have bounded, room-owned terminal cleanup.

## Companion changes included since 0.12.8

Configured action routes appear consistently in connection catalogs. Pending
action summaries remain in History while source results are outstanding;
background updates respect quiet preferences, and returned replies are delivered
and labeled without turning pending activity into a completed result.

Saving setup does not start a model session or call, request microphone or camera
access, or verify a provider connection. Starting the application server opens
and migrates that installation's shared database. An installation that must keep its current Companion
process unchanged should therefore defer updating that whole installation.

## Native setup and updates

Complete bundles are available for Windows, macOS and Linux on x64 and ARM64,
including macOS application archives. A standalone installation does not require
developer tools, a system Node or Python runtime, or a local Instance. Open the
app to create a local account, select a saved contact or connect an existing
agent, and configure missing voice settings in the browser.

New personal installations use literal-loopback HTTP and an installation-local
password. Existing HTTPS and OS-account configurations retain their access
policy. Selecting a saved contact preserves its profile, grants and room sessions.

Whole-bundle updates record update and recovery requests durably. An OS-managed
worker can survive the old app stopping; the restored app has an independent
managed lifetime. Active calls, accepted work and uncertain effects can defer
updates, and an enrolled installation retains its existing updater owner.

For supported native-bundle installations, rollback preserves current user data
while restoring application files. Recovery
of a replacement that has not reported authenticated status uses only its captured
native generation and profile, requires actual exit before exchanging bundles,
and verifies the previous application's health separately. Unknown outcomes do
not authorize a repeated launch or stop. Inventory and file-hash validation remain
complete; bounded verification and copy workers finish before publication or
cleanup. Protected long paths and mutable journal handling are included.

## Known limits

The browser's package **Check** still waits for preparation to finish. Ordinary
Windows 11 tests have exceeded its 40-second response deadline, including an
attempt where source-bundle validation consumed most of that time. A lost reply
does not prove cancellation: preparation may continue and save a result later.
Background checking with a quick acknowledgment and progress updates is not
implemented in this release. Do not repeat an uncertain request as a recovery
step. Full ordinary Windows managed-update acceptance remains open.

Legacy installations without a native bundle baseline and compatible service
registration need a separately qualified migration; the new updater does not
automatically adopt every older service layout.

Six native CI targets passed, including installation with developer tools absent
from the product's PATH. Windows x64 hosted coverage uses Windows Server;
ordinary Windows 11 results are separate. This is not fresh-OS, reboot, physical
microphone/camera, signing or notarization qualification. The release does not
claim a universal performance improvement.
