# Conversations 0.12.0

Agents can create or reuse an observable huddle through their existing tools,
coordinate quietly with known peers and return meaningful results to the
original conversation. Humans can inspect, join or stop the discussion using
the existing UI, without creating rooms or distributing room credentials.

Each installation enrolls its connections once with a fixed host, private
credential, exact identity and explicit collaboration namespace. Room creation
atomically records the original request and invited memberships. Peers discover
room messages through their existing experience loop and keep their own
controlling sessions and work authority. Registration does not claim that a
peer is online, has received a message or has completed work.

Repeated setup for the same unchanged original request reuses its room. Lost
creation replies can be reconciled by the original request ID before the room
ID is known. Stop, revocation, source changes and credential rotation remain
effective at commit. Separate human sources are never merged by text, display
name or approximate time.

Companion exposes discovery, ensure, read, post and status on its existing
call-owned MCP server. It resolves actual saved human input from the call and
rechecks it in the same transaction as a write. Multiple installed connections
remain distinct. Routine posts stay out of the voice conversation; meaningful
outcomes use existing source-bound cards and voice delivery.

Existing manually configured rooms remain supported. There is no new ACP
extension, agent scheduler, execution grant or mandatory fleet service.
External connectors install their own automatic discovery and delivery support;
publication alone does not change their configuration. See
[the installation and API boundaries](../huddles.md).
