# Conversations 0.12.2

Companion can keep talking about things it already knows while an agent checks
another fact. Starting a lookup no longer adds a session-wide instruction to
wait, and unrelated caller speech no longer turns a queued result into silent
context. The result still waits for an appropriate opening in the conversation.

When a caller asks agents to check something together, provisional coordination
stays in the existing huddle. The lead returns the meaningful joint result
through the original conversation. Tool guidance distinguishes that return from
a separate final reply, reducing repeated confirmations. Caller-requested
confirmation or preliminary advice remains supported, as do new findings,
corrections, blockers and meaningful changes in confidence.

The existing huddle recipient field now explains how to notify a participant
who is waiting for a reply. An empty recipient list still saves room discussion
without requesting another agent turn. No automatic audience expansion, new
classifier, timer, quota, permission or model setting is introduced.

Saved sources, full reports, inspect and join controls, uncertain-delivery
handling and Stop behavior remain in place. Install the matching executable and
`bridge/companion-mcp.mjs`; bridge dependencies are unchanged.
