# Conversations 0.13.1

Adds an explicit Linux transition for qualified pre-native Conversations 0.9
installations. The installation owner captures and stops the existing service;
adoption preserves its custom definition, configuration, credentials, sessions,
history and retained outcomes before establishing a genuine native bundle.

The raw-state audit refuses active or queued work before startup recovery can
normalize it. Exact historical unknown inputs remain unchanged and unreplayed.
Candidate startup uses the original service and keeps work admission closed
until process identity, authenticated health and saved-state preservation pass.
Pre-admission recovery requires exact candidate exit before the old executable
reopens the current database; it never restores a stale database snapshot.

After verified restoration of the old service, the owner can explicitly begin
a fresh adoption with a new capture and transaction UUID. The previous capture,
origin, journal and admission rows remain in immutable history. The new attempt
audits current state again, preserving changes made after restoration. An
uncertain outcome does not trigger a new attempt or authorize replay.

Legacy adoption remains limited to the supported Linux Conversations 0.9 schema,
excluding Companion homes and installations with an enrolled updater. Exact
service, update and recovery qualification is separate from source support or
package build results; this change does not claim a live migration or acceptance
on every native platform.

See [legacy adoption](../legacy-adoption.md) for the supported schema, ownership,
failure states and scope limits. This release does not change Companion or the
paused background-CHECK design. Existing 0.13.0 assets remain immutable.
